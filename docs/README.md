# Documentation index

Read in this order.

| # | File | Purpose |
|---|---|---|
| 1 | `PROJECT_STATE.md` | Living status. Updated at the end of every session. |
| 2 | `workflow/WORKFLOW.md` | How work is done, session protocol, Git rules, how to use the prompts |
| 3 | `phases/` | One file per phase: goals, tasks, exit criteria, and the prompts |
| 4 | `product/PRD.md`, `product/use-cases.md`, `product/product-spec.md` | PRD with requirement status, use cases with acceptance, spec and MVP scope |
| 5 | `product/scoring-methodology.md` | Draft formulas for every score (frozen during Phase 1) |
| 6 | `research/` | Competitor matrix, verified facts, research log, open verification items |
| 7 | `architecture/` | Overview, IR and report schema, job model, repository structure |
| 8 | `adr/` | Architecture decision records |
| 9 | `security/` | Threat model and security acceptance criteria |
| 10 | `ux/` | Visual direction, information architecture, wireframes, design tokens, states, accessibility |
| 11 | `evaluation/evaluation-plan.md` | How accuracy, performance, and usefulness are measured |
| 12 | `roadmap/` | MVP plan and the prioritized backlog |
| 13 | `registers/decision-register.md` | Requirements, assumptions, decisions, risks, evidence |
| 14 | `learning/` | What, why and where for each phase, plus college question banks |
| 15 | `reference/` | CLI, rules and analyzer references |
| 16 | `academic/` | Empty until the project is complete |

## Writing rules

- No em dashes anywhere. Use commas, colons, parentheses, or separate sentences.
- Mark every external fact as Verified (with source and date), Unverified, or Assumption.
- Status words for decisions: Proposed, Under investigation, Validated, Accepted, Rejected, Deferred.
  Validated means technically proven. Accepted means the owner approved it. They are different.
