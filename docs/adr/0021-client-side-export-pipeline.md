# ADR 0021: Client-side export pipeline

- Status: Proposed
- Date: 2026-10-25
- Technical validation: SVG and PNG export of the module map verified in a browser (light literal palette, 29 module boxes, PNG blob created). PDF through the print dialog was not exercised.
- Related: ADR 0019

## Context

Every chart and diagram must be downloadable in formats usable in documents, without sending anything to a server.

## Decision

All charts use one class based stylesheet generated by `chartCss(palette)`. On screen the palette is CSS variables. For export the same markup is wrapped by `buildExportSvg` with literal light colors, a title, repository, commit, date, tool version, legend and a footer.
SVG is the master format. PNG is the SVG drawn on a canvas at 2x. PDF opens the SVG in a hidden frame and calls the print dialog (Save as PDF). JSON gives the data behind the view. Graphs also export Mermaid and DOT text produced by the engine.

## Alternatives considered

Server-side rendering of images (uploads data, needs a service). A PDF library (extra bundle, little benefit over print). Screenshots of the DOM (theme dependent, low quality).

## Consequences and tradeoffs

PDF depends on the browser print dialog. PNG uses the browser canvas and has size limits for very large diagrams. Fonts in exports are the system fallback stack, not Geist.

## Security and operational implications

All text in exports is escaped. Nothing leaves the browser.

## Conditions for reconsideration

Users need batch or automated exports (the CLI already exports Mermaid, DOT and SVG).
